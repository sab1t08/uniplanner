# سامانه‌ی هوشمند زمان‌بندی دانشگاهی

## اجرا
```
pip install -r requirements.txt
ollama pull qwen2.5:7b
streamlit run app.py
```
دیتابیس خروجی (`schedules_output.db`) در اولین اجرا ساخته می‌شود.

## بررسی داده‌ها و تست
```
python -m db.validate                         # مشکلات داده‌ای که هیچ سولوری حل نمی‌کند
python -m unittest discover -s tests -t .     # تست‌ها
```

## ساختار
| مسیر | وظیفه |
|---|---|
| `config.py` | همه‌ی ثابت‌ها (روزها، اسلات‌ها، وزن‌ها، مدل، مسیرها) |
| `db/` | اتصال، ساخت جدول، تنها لایه‌ی SQL (`repo.py`)، اعتبارسنجی داده |
| `solver/problem.py` | تبدیل داده به مسئله (ادغام درس‌های مشترک، قفل‌ها، برنامه‌ی قبلی) |
| `solver/cpsat_model.py` | مدل OR-Tools CP-SAT |
| `solver/heuristic.py` | چیدمان ابتکاری (پشتیبان و نقطه‌ی شروع CP-SAT) |
| `solver/engine.py` | انتخاب موتور و بازبینی خروجی |
| `solver/checker.py` | بازبینی قطعی تداخل‌ها و قیدها |
| `solver/service.py` | چیدمان، جابه‌جایی، تعویض، تغییر استاد/کلاس، قفل، Undo |
| `solver/reports.py` | گزارش کیفیت |
| `agent/` | ابزارها (Function Calling)، resolver نام‌ها، router، قالب‌بندی بدون LLM |
| `ui/render.py` | جدول هفتگی HTML و خروجی Excel/CSV |
| `app.py` | فقط رابط کاربری |

## قیدها
**سخت:** تداخل استاد، کلاس و دانشجو؛ تطابق نوع کلاس؛ صلاحیت استاد؛ سقف واحد استاد؛ قفل‌ها؛ جلسه‌های یک درس در روزهای متفاوت.
**نرم (تابع هدف):** حداکثر پوشش دروس، پرهیز از ساعت اول و بیش از ۲ جلسه در روز، کمترین جابه‌جایی نسبت به برنامه‌ی قبلی.
